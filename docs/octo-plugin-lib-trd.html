Octo Plugin Lib

业务中立的 Go 领域库：统一 Plugin Schema、校验、内容 Hash 和宿主私有 MySQL 三表 CRUD。

不独立部署 三表 CAS

1. 系统边界

Lib 拥有

四类 Plugin、两态状态、三类 Relation、内容 Revision、Schema、Hash、MySQL Store 与 conformance。

宿主拥有

HTTP、身份、鉴权、审计、幂等、Workspace/Space、对象存储、Secret、Runtime 与产品生命周期。

明确不包含

跨宿主传输封装、市场版本与来源、发布回 Market、cowork_plugin_audit_log 和网络服务。

Market、Loop、Buddy 及其他宿主引用同一个库，但使用各自的 database/schema、账号与 Bucket。

只有会创建 Revision 的操作向 Lib 传入 Actor 并写入 created_by； SetStatus 与 ReplaceRelations 的操作人授权和审计属于宿主。

3. 文件与内容身份

  • raw 只允许 UTF-8 raw_content。
  • storage 必须提供 content_size/content_hash，不允许 raw_content/storage_uri。
  • path 最多 512 字符，拒绝绝对路径、Windows 盘符路径、反斜杠、dot/parent/空段、控制字符、重复 path 和尾斜杠。
  • MIME 最多 255 字符；非空值按 Unicode White_Space 判断；content_size 最大 9007199254740991。
  • 文档总大小、附件总大小和附件数量由宿主在 HTTP、上传和存储入口限制；Lib 不充当请求体限流器。

Lib 不读取 storage 对象字节。宿主按 scope_id + content_hash 稳定定位私有对象。

四类 Plugin 都允许显式 plugin_json: null。非空 Package 中，Expert 需要 AGENTS.md 且无 Connector 描述；Skill 需要 SKILL.md 且无 Connector 描述；Expert Team 只能包含 AGENTS.md；Connector 按下表约束。

plugin_hash = sha256(canonical(manifest_json) + canonical(plugin_json))。Attachment 按 path 排序，其数组顺序不影响 Hash；其他数组保序。Canonical JSON 不等同于 RFC 8785/JCS。 数字词法及规范化结果最长 10,240 字符，指数范围为 -10000～10000；一份 JSON 文档累计数字展开增量最多 10,240 字符，避免少量指数词法放大为无界内存；对象键按 Unicode scalar value 升序排列， 对合法 UTF-8 等价于 UTF-8 字节序，不得使用 UTF-16 code-unit 默认顺序。字符串使用 Go encoding/json 规则，<、>、&、U+2028、U+2029 使用 \u 转义。对象排序 O(k log k)，内存与规范化输出之和同阶； JSON 最多嵌套 512 个 object/array 容器。UUID 不校验 UUID version 或 variant；孤立 UTF-16 surrogate 转义被拒绝。跨语言实现必须同时执行 JSON Schema、semantic fixtures 和 golden Hash。

4. ER 与事务

plugin (scope_id, id)
  ├── 1:N plugin_revision (scope_id, plugin_id, revision_no)
  ├── current → plugin_revision via (scope_id, id, current_revision_no)
  └── N:N plugin_relation (scope_id, source_plugin_id, relation_type, target_plugin_id)
  • scope_id VARCHAR(40)；revision_no 与 lock_version 为 INT UNSIGNED / Go uint32。
  • Revision No 在锁定 Plugin 行的事务内从 1 递增，不使用全表 AUTO_INCREMENT。
  • Create 固定 ACTIVE；Update、SetStatus、ReplaceRelations 共享 lock_version CAS。
  • ARCHIVED Plugin 的普通 Update（包括 no-op）均拒绝；Restore 可追加内容 Revision，但保持 ARCHIVED 且不改变当前关系。
  • CreateGraph 校验闭包后一次提交；失败全部回滚。
  • MySQL DSN 必须含 parseTime=true&loc=UTC；Install 实际往返 UTC 微秒时间并拒绝错误配置。
  • Revision 不可变由公开 API/Store 保证，不使用数据库 trigger；宿主数据库账号不得用原始 SQL 绕过。
  • 结构指纹已在 MySQL 8.0.46 和 8.4.10 验证。
  • Get、List 和 ListRevisions 的普通调用使用 REPEATABLE READ 快照事务，但不声明 READ ONLY，避免数据库代理误路由到延迟副本；宿主连接必须满足读己之写。Get 的 Plugin、Revision、Relation 一致，两个列表的总数与当前页一致。WithTx 读取遵循宿主事务隔离级别。
  • manifest_json/plugin_json 使用 utf8mb4_bin LONGTEXT 精确保留 Canonical JSON；不用会重编码或拒绝部分公共数值的 MySQL JSON 解析器。Get/GetRevision 复核 Canonical 字节、公共契约和 plugin_hash，内容漂移时返回 INTEGRITY_FAILURE；List 不读取大文件树，只校验查询命中并返回行的 Manifest 及主表投影；ListRevisions 只返回元数据，使用内容或 Hash 前调用 GetRevision。
  • plugin.description 是当前 Manifest description 的事务性查询投影，只服务名称/描述搜索；Manifest 仍是权威真源，读取时校验一致。
  • 生产环境分离迁移账号与最小权限运行时账号；调用方最低 Go 语言版本为 1.25，本仓库使用 Go 1.25.11 工具链验证。
  • List 使用页码/offset；单次调用一致，但不提供跨请求快照。并发更新可能使项目换页，调用方应刷新。

旧 MySQL JSON 列不能直接 ALTER 为 LONGTEXT：数据库已重编码的数据无法恢复原 Canonical 字节。旧实验库必须从可信原始内容经当前 Lib 重新校验并导入新空库。若查询投影被越权改坏，按真实描述筛选可能漏行；发现漂移时停止写入并由管理员从可信来源重建，不提供在线猜测修复。

6. 宿主与 Market

Market 保存 Space 公开 Plugin；Loop/Buddy 保存各自私有副本。Market 招募时传输当前 闭合关系图与附件原始字节，目标宿主生成新 ID 并深拷贝。Lib 不定义跨服务 HTTP，也不允许 目标宿主直连 Market 数据库或 Bucket。

mcp必须有根目录 mcp.json；嵌套 Skill 可选
cli必须有根目录 cli.json 和至少一个 skills/<name>/SKILL.md
skill-only必须包含根目录 token-schema.json，并至少包含一个 skills/<name>/SKILL.md；附件顺序不表达业务语义
openconnector必须有根目录 mcp.json

7. 验收门禁

Schema/fixtures/golden、unit/race/vet/build、fresh MySQL 安装与重复安装、CRUD、CAS、 scope 隔离、事务回滚、图原子性、结构漂移和独立 GOWORK=off 消费者必须全部通过。

稳定错误码：invalid_json、invalid_field、 invalid_plugin_type、invalid_relation_type、 invalid_relation、invalid_attachment_path、 duplicate_attachment_path、invalid_attachment_content、 hash_mismatch。

Service 返回契约校验错误时同时保留 pluginstore.ErrInvalidArgument 与原始 plugin.ValidationError，宿主通过 errors.As 读取稳定的 Code/Path，不得解析错误文本。

发布首个稳定版本后，同一 Schema ID 的内容不可变。
